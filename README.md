# CreatorOS AI

**Your Audience. Your Expertise. Your Business.**

CreatorOS AI is an AI-powered business launchpad for Indian creators, influencers, coaches and educators. Enter an Instagram handle (or a short description of what you create) and the app will:

1. **Analyse your creator profile** — niche, expertise, audience segments, audience problems and monetisation angles (real LLM analysis).
2. **Discover what you can sell** — 2–4 personalised digital product ideas (ebooks, courses, cohorts, consultations, communities…) with **India-specific INR pricing**, pricing rationale, difficulty and launch strategy.
3. **Generate your storefront** — headline, bio, about page, CTA copy and a recommended theme (Minimal / Bold / Editorial / Playful).
4. **Let you edit everything** — a visual editor with live preview, undo/redo, theme switching and a conversational **Creator Copilot** that actually applies your natural-language instructions to the store data ("make my bio friendlier", "change the price to ₹699", "make it look luxury").
5. **Publish** — a real public storefront at `/store/{slug}` with working CTAs (WhatsApp / email / Instagram), plus one-tap WhatsApp sharing.

All AI outputs are generated by **live LLM calls** — nothing is hardcoded or mocked.

## Tech stack

| Layer | Choice |
|---|---|
| Framework | Next.js 16 (App Router) + TypeScript |
| Styling | Tailwind CSS 4 + shadcn/ui + Lucide icons |
| State | Zustand (persisted session, undo/redo history) |
| Database | Prisma ORM - SQLite locally (`db/custom.db`), Postgres on Vercel (auto-synced during build) |
| AI | Gemini (primary) + Groq (fallback) chat APIs, called server-side only, with Zod-validated structured JSON output |
| Validation | Zod on every LLM response and API body |

> Note: this build uses Prisma for persistence (SQLite locally, Postgres on
> Vercel) and the Gemini/Groq REST APIs for model calls. The data model
> (creators / stores / products / ai_conversations) maps 1:1 between the two.

## Getting started

```bash
# 1. Install dependencies
bun install

# 2. Configure environment
cp .env.example .env       # then edit if needed

# 3. Push the database schema
bun run db:push

# 4. Run the dev server
bun run dev
```

Open the app, click **Build My Store**, try one of the demo creators (Aditi / Rahul / Meera) or describe your own content, and follow the 3-step flow.

## Environment variables

See `.env.example`. In this sandbox the AI SDK reads its credentials automatically; no client-side keys exist — all AI calls happen in API routes.

## API surface

| Route | Method | Purpose |
|---|---|---|
| `/api/analyze` | POST | Creator intelligence analysis (A) |
| `/api/products` | POST | Product discovery / regenerate / more (B, C) |
| `/api/storefront-copy` | POST | Storefront copy + theme recommendation (D, E) |
| `/api/store` | POST | Create store + products, unique slug |
| `/api/store/[key]` | GET/PATCH | Read public store (by slug or id) / save edits |
| `/api/copilot` | POST | Conversational editing with structured actions (F), logged to `ai_conversations` |
| `/api/instagram` | POST | Best-effort public profile lookup, graceful fallback (no scraping) |

## AI reliability

- Structured JSON outputs validated with Zod (`src/lib/ai/schemas.ts`)
- Automatic retry with JSON-repair reminders on invalid output (`src/lib/ai/llm.ts`)
- Timeouts, friendly error copy, retry buttons on every generation screen
- Copilot price changes require explicit confirmation before applying
- All prompts live in `src/lib/ai/prompts.ts`, separate from frontend code

## Deploying to Vercel

1. **Push to GitHub** - secrets stay local: `.gitignore` excludes `.env*`
   (except `.env.example`), logs and local database files, so nothing private
   is committed.
2. **Import the repo on Vercel** (vercel.com/new). Build settings are already
   configured via `vercel.json` + `scripts/vercel-build.sh` - no changes needed.
3. **Connect a database** - Vercel dashboard > your project > **Storage** >
   **Create Database** > **Neon (Postgres)** (free tier is fine). The
   integration sets `DATABASE_URL` automatically, and the next build creates
   all tables. (Alternatively add any `postgres://` URL manually under
   Settings > Environment Variables.)
4. **Add your AI keys** under Settings > Environment Variables:
   - `GEMINI_API_KEY` (+ optional `GEMINI_MODEL`, default `gemini-3.8-flash`)
   - `GROQ_API_KEY` (+ optional `GROQ_MODEL`, default `llama-3.3-70b-versatile`)
   - `TAVILY_API_KEY` (optional - live competitor pricing research)
   - `INSTAGRAM_SCRAPER_API_KEY` (optional - Instagram profile lookup)
5. **Redeploy** after adding variables, and you're live.

### Store URLs

Published stores live at `https://<your-domain>/store/<slug>`, for example
`https://creatoros-ai.vercel.app/store/aroma-roots-skincare` - the link never
contains a platform name. Share links are built from the browsing origin, or
from `NEXT_PUBLIC_SITE_URL` once you attach a custom domain (e.g.
`https://www.mystore.in`) in Settings > Environment Variables.

### Local vs production database

Local development keeps using SQLite (`prisma/schema.prisma`). Vercel builds
use the Postgres variant (`prisma/schema.postgres.prisma`) - the data models
are identical, so no code changes are needed when you deploy.
